# VPP2 in LoongForge embodied

This integration ports the action-only LIBERO stage of VPP2: a frozen
Wan2.1-I2V-14B video DiT, a trainable action DiT, and MoT mixed attention.
The numerical modules are kept under this package so the model registry and
embodied trainer can load them without changing the BASE repository.

## Assets

Set the two roots used by the examples first. They are deliberately environment
variables so the integration does not depend on a particular mount layout:

```bash
export VPP2_ASSETS_ROOT=/path/to/vpp2_assets
export VPP2_BASE_ROOT=/path/to/video-prediction-policy-2
# Optional when the 32.8-GB video checkpoint lives outside the asset root.
export VPP2_VIDEO_CHECKPOINT=$VPP2_ASSETS_ROOT/libero_video_step010000.pt
```

Provide these assets below `VPP2_ASSETS_ROOT` before launching a run:

- Wan2.1-I2V-14B auxiliary assets (`Wan2.1_VAE.pth` and the OpenCLIP visual
  checkpoint).
- `video_step010000.pt`, the frozen video-DiT checkpoint.
- `action_init.pt`, the strict 1010-tensor action-backbone initializer. The
  four projection tensors and proprio encoder are intentionally initialized
  separately, as documented by the checkpoint policy.
- LIBERO LeRobot directories, `dataset_stats.json`, and the precomputed text
  embedding cache (128-token context for the released action config).

The cache is generated by the pinned BASE implementation. From the BASE
checkout, prepare a config with the four LIBERO dataset directories and run:

```bash
cd "$VPP2_BASE_ROOT"
PYTHONPATH="$VPP2_BASE_ROOT/src" python -m vpp2.libero.cli \
  text-cache --config /path/to/action_config.yaml --device cuda:0 --batch-size 1
```

The resulting `text_cache_real/manifest.json` and per-prompt files must be
visible at the path passed as `data.text_embedding_cache_dir`. The cache tag
must remain `wan21i2v14b480p`; changing it changes the dataset lookup keys.

The typed defaults are in `modeling_configuration_vpp2.py`; override paths in
the model config rather than editing the package. The standard launcher uses
eager (non-meta) construction so DDP can wrap a fully materialized model; its
checkpoint load is strict. Probe scripts can still request `init_on_meta=True`
and call `materialize()` explicitly.

## Launchers

```bash
# canonical DDP smoke/finetune recipe
bash examples/embodied/vpp2/run_vpp2_sft_ddp_finetune.sh

# closest optimizer-state approximation to BASE ZeRO-2
bash examples/embodied/vpp2/run_vpp2_sft_ddp_zero1_finetune.sh

# FSDP fallback when the DDP recipe does not fit
bash examples/embodied/vpp2/run_vpp2_sft_fsdp_finetune.sh
```

Useful environment overrides include `GPUS_PER_NODE`, `DATASET_PATH`,
`OUTPUT_DIR`, `TRAIN_ITERS`, `PER_DEVICE_BATCH_SIZE`, `VPP2_ASSETS_ROOT`,
`VPP2_DATASET_ROOT`, `VPP2_VIDEO_CHECKPOINT`, and `VPP2_BASE_ROOT`. The
canonical
launcher uses AdamW `(0.9, 0.95)`, `lr=1e-4`, 500-step linear warmup followed by
cosine decay to `1e-6`, BF16, and no-op gradient clipping (`--clip-grad 0.0`),
matching the effective BASE DeepSpeed configuration.

## Parity notes and known deviations

- BASE uses Accelerate + DeepSpeed ZeRO-2; embodied LoongForge has no equivalent
  ZeRO-2 backend, so the primary recipe is DDP + ZeRO-1 + FP32 master params.
- Fixed-batch forward, activation, eval, and step-0 gradient probes match the
  pinned BASE exactly. Long optimizer curves show a small cross-engine BF16
  trajectory drift; see the task evidence under `/workspace/vpp2_port/evidence`.
- A literal batch of 32 on one 80-GiB card OOMs while building the video KV
  cache. The parity probes therefore use identical microbatch-4 partitions;
  canonical training remains an 8-GPU, per-GPU batch-32 recipe.
- The VPP2 activation probe is default-off. Set `VPP2_VPROBE=1` only in an
  evidence probe; production launches do not install hooks.

The BASE repository is read-only for this port. Checkpoint loading is strict:
missing or unexpected tensors are errors, and VAE/CLIP are pinned to FP32/FP16
and eval/frozen respectively.
